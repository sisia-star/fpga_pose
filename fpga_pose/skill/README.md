# FPGA运动姿态识别项目技能包说明

本技能包根据PYNQ-Z2运动姿态识别项目与大模型协作开发的经历整理，面向开展视觉识别、FPGA计算卸载和板端部署的队伍。内容分为“提示词工作流、案例模板、校验脚本、踩坑清单”四类，供后续项目根据自身条件选择和调整。
本文引用的工程版本`fpga_pose_parallel_ai`，已测试平台为PYNQ-Z2、PYNQ 3.0.1和Vivado 2022.2。电脑可以辅助推理：PL承担图像预处理、指定输出卷积及姿态距离计算，PS承担数据搬运和训练状态管理，电脑承担人体检测、网络前缀与关键点后处理。
使用前提：本文件是独立说明；校验脚本、RTL、位流、模型和数据需从完整工程中取得。不要认为仅有本README即可运行硬件验证。跨器件、跨模型或更改接口后，应重新检查约束并执行验证。

## 一、提示词工作流
### 1. 软硬件任务划分工作流
适用范围：需要在电脑、PS及PL之间划分视觉算法，或计划把指定网络层、特征计算和分类计算迁移到FPGA的项目。若允许电脑辅助，可参考本项目的协同方式。
使用方法：
1. 准备板卡型号与资源、Vivado版本、模型结构和输入输出尺寸、是否允许电脑辅助、目标帧率及已有耗时记录。
2. 让大模型按采集、预处理、检测、姿态推理、特征、分类、状态机和展示拆解任务，列出每步的输入、输出和依赖。
3. 结合算术并行性、存储空间、总线传输和工具链，将各任务分配给电脑、PS或PL；说明PL输出如何参与最终结果。
4. 定义形状、数值范围、量化尺度、存储步长、AXI或DMA接口、完成条件和失败退出方式。
5. 以仿真、软件整数参考和板端实测核对计算，再按端到端性能结果修正方案。
可复用提示词：请依据以下板卡资源、模型输入输出、工具链及性能目标，拆解计算流程并分配给电脑、PS和PL。对每一项硬件候选任务列出数据形状、数值格式、接口、资源与传输成本、实际输出用途和可执行的验证方法。将未提供或未测量的信息标为待确认，不能根据DSP占用直接宣称系统提速。
本项目观察与已验证效果：项目尝试板端运行MediaPipe时遇到帧率过低的问题；之后采用电脑、PS和PL协同。最终PL实现2×2均值降采样、36路卷积乘加、32路距离与稳定Top-5，并通过指定输入下的硬件整数一致性验证。
失效条件：若不允许电脑辅助、要求完整模型板端部署、模型或量化规则改变，原划分和验证结论不再直接适用；若没有真实输出链路或板端验证，也不能仅凭方案认定FPGA已有效参与计算。
### 2. 根据报告定位性能瓶颈的工作流
适用范围：比较两个工程版本的资源、时序及运行性能，或分析计算卸载后为什么整体速度没有改善。
使用方法：
1. 确认两个报告对应的器件、工程版本、布局布线阶段和时钟约束，提取LUT、FF、BRAM、DSP、WNS、WHS、TNS和THS。
2. 对同一输入分别测量采集、预处理、网络计算、卷积调用、特征与分类，记录CPU、PS、DMA/PL和网络的计时起止点、预热与重复次数。
3. 对照原始结果确定瓶颈，再提出减少数据复制、通信或改进调度等优化方案。
可复用提示词：根据两版Vivado报告和相同输入条件下的原始计时记录，分别比较资源、时序、纯硬件周期和包含通信的调用耗时，指出主要开销、测量边界和未覆盖的测试。不要把DSP数量倍数写成加速倍数，不要用CSV留出准确率代替摄像头或真人测试结果。
本项目观察与已验证效果：DSP使用132/220，在100 MHz约束下满足本次时序要求；分阶段对比发现PS数据整理与通信存在明显开销，当前测试未显示相对电脑CPU的端到端速度优势。
失效条件：芯片、模型、输入、CPU、线程或计时范围不同而没有统一口径时，不能直接比较；缺少原始记录时只能提出待验证的假设。

## 二、案例模板
### 1. 软硬件工程与接口模板
适用范围：增加PL计算核、迁移网络层、调整数据通路或适配分类特征。
使用方法：在开始编码前填写以下字段，交由硬件、软件和测试人员共同核对；实现变化时同步更新。
本项目验证：图像核、卷积核与距离核均有配置、计算及结果检查流程。模板整理自接口不匹配、复位接错和不同版本文件混用的排错经历。
失效条件：设备、时钟、协议、模型、权重或数值格式变化后，必须重新填写和验证，不能沿用原报告宣称新方案通过。
### 2. 动作适配案例模板
适用范围：增加动作类别，或排查侧机位姿态检测点不全导致的动作识别问题。
使用方法：依次填写“动作目标—必要关键点—特征公式—可见性与有效性条件—动作阶段—数据来源—测试方法—失效场景”。同步修改训练数据处理、实时特征、板端校验和测试。
本项目示例：俯卧撑从可见侧肩、肘、腕构建3维几何特征并补齐至99维；选侧稳定后锁定，再按起始、到位、返回阶段判定完整动作。固定样本与特征测试检查维度和规则一致性；真人测试应另外记录实际次数、系统次数、漏计、误计和机位。
失效条件：核心关节出画、近侧也被严重遮挡或画面多人干扰时，无法保证识别；鸟狗式需要对侧肢体关系，不能直接套用俯卧撑的单侧规则。自动选侧能够减少频繁切换，不保证完全消除识别错误。

## 三、校验脚本
### 1. `check_before_load.py`：加载前文件检查
适用范围：PYNQ版工程加载位流之前检查文件存在性、哈希、HWH接口及相关配置。
使用方法：在完整工程根目录，使用能导入工程依赖的Python运行：
python3 check_before_load.py
程序输出bit/hwh文件大小、SHA256及HWH检查结果。该步骤只检查文件，不下载位流、不读取FPGA寄存器。
失效条件：文件缺失、解析失败、版本或预期接口不匹配时停止后续步骤；即使预检通过，也不能说明实际DMA或卷积计算已通过验证。
### 2. `verify_convolution.py`：卷积硬件一致性检查
适用范围：检查当前位流和实际训练权重下，PL卷积整数输出是否与CPU整数参考一致。
使用方法：先结束训练并正常停止板端实时服务；确认没有其他Notebook占用硬件和8081端口。在完整工程根目录、使用PYNQ环境运行：
sudo /usr/local/share/pynq-venv/bin/python3 verify_convolution.py \
  --output conv_recheck.json
脚本使用真实权重和极值、随机输入，比较CPU int64参考与FPGA输出并生成JSON。已有记录中，3组输入各195个结果一致。
失效条件：PYNQ环境、硬件权限、服务锁、位流、权重或驱动不匹配时应停止并保留错误；输入格式或量化规则变化后需重新验证。整数参考一致不代表浮点逐位一致，也不代表真人识别准确率。
### 3. `verify_parallel_hardware.py`：距离与投票检查
适用范围：检查八种已存动作模型的PL距离计算、Top-5相关结果及PS投票是否符合软件参考。
使用方法：与卷积测试相同，先停止实时服务、独占硬件，再在完整工程根目录运行：
sudo /usr/local/share/pynq-venv/bin/python3 verify_parallel_hardware.py \
  --output distance_recheck.json
检查程序输出的模型数量、查询数量、一致性和JSON记录。完成全部独占测试后，按系统实际服务管理方式恢复服务。
失效条件：模型、标签、阈值、位流或特征协议不配套时，结果不应作为验收依据；该脚本使用已存特征查询，不是独立留出准确率或真人测试。
### 4. `hardware/build_vivado.tcl`：构建与报告检查
适用范围：使用Vivado 2022.2构建本工程硬件，并检查接口、仿真、综合、布局布线和报告。应通过完整工程的`start_vivado_2022_2.tcl`入口运行。
使用方法：安装PYNQ-Z2板卡文件，核对入口中的板卡仓库路径，在空白Vivado会话中用`source`命令运行入口。检查报告器件、时钟约束、资源和时序结果，并记录同次构建的bit/hwh哈希。
本项目结果：最终版在100 MHz约束下满足该次时序要求；这不代表任意修改后的设计仍满足要求。
失效条件：板卡文件、工具版本、RTL、时钟约束或器件改变后需重新构建和验证；位流生成成功也不能替代板端硬件自检。
